## 二、三项检查的判定规则

### C1：命令行给出的随机种子是否真正生效

**看什么**：训练入口（通常 `scripts/train.py`）、参数解析与配置装配（`helpers.py` 或 `task_registry.py` 或等价物）、`set_seed` 的定义与调用点。

**步骤**：

1. 找 `--seed`（或 argparse / absl / hydra 等价的 seed 参数）定义处；
2. 看它被写到哪个配置对象（`env_cfg.seed`？`train_cfg.seed`？`cfg_train.seed`？）；
3. 找 `set_seed(...)` 的**调用点**，看实参取自哪个对象；
4. 再确认这个实参在**调用时刻**是否已经被赋值——注意 `update_cfg_from_args`、`make_env` 的调用先后，以及"实参为 None 时跳过赋值"之类的守卫。**先后顺序错了，值就进不去。**

**判定**：

- **是**：`--seed` 的值最终被 `set_seed` 用上（直接传参，或先写入 `env_cfg.seed` 且在 `set_seed` 调用之前完成）；
- **否**：`--seed` 写进了 A 对象，而 `set_seed` 读的是 B 对象，两者之间没有赋值关系；
- **无法判定**：关键文件缺失，或调用链跨文件无法闭合。

**必须一并判断的两个陷阱**（这两条决定 C1 的结论，不要漏）：

1. `env_cfg.seed = train_cfg.seed` 这类"配置间复制"**本身不算命令行生效**，要看 `train_cfg.seed` 是否来自 `args.seed`；
2. 若 `update_cfg_from_args` 的形参在本次调用中为 `None`，则其中的 `env_cfg.seed = args.seed` 不执行——**此时即使代码里有这一行，也等于没有**。要判断该形参在 `make_env` 的实际调用链里是否被传入。

### C2：评估脚本是否显式关闭随机化

**看什么**：`scripts/play.py`、`evaluate.py`、`play_*.py` 一类脚本。

**判定**：

- **是**：脚本显式关闭了域随机化与课程（例如 `domain_rand.enabled=False`、`curriculum=False`），或显式设定确定性；
- **否**：存在评估脚本，但上述开关未关闭，或只关闭了一部分；
- **无法判定**：没有评估脚本，或脚本存在但看不出开关状态。

**注意一**：仓库根本没有评估脚本 → 判"无法判定"，不要判"否"。
**注意二**：关的是**不存在的字段**（例如 `domain_rand` 里根本没有 `enabled`，代码用 `getattr(..., None)` 静默跳过），按"**否**"判，并在证据里写明"关闭动作无效"。

### C3：故障/扰动的注入是否有落地核对

**看什么**：任何写故障、扰动、随机化的代码位置，及其附近是否有核对。

**判定**：

- **是**：在写入物理量（力矩上限、增益、外力等）的位置附近，存在断言或显式比较，用于确认该写入确实生效；
- **否**：存在注入代码，但没有任何核对；
- **无法判定**：仓库没有注入代码，或相关文件未被取到。

**注意**：单元测试里的断言、CI 脚本里的检查**不算**（它们不检查运行时是否按配置注入）。`assert` 出现在与注入无关的位置也不算。

## 三、填写方式

目标文件：`[workspace]/56-双人编码-20261102\编码表-第二编码者.csv`

| 列 | 填什么 |
|---|---|
| `repo` | 已给出，不要改 |
| `C1` `C2` `C3` | 是 / 否 / 无法判定（三选一，不要写别的词） |
| `证据` | 一句话 + **文件:行号**（例：`helpers.py:135 cfg_train.seed=args.seed`） |
| `备注` | 拿不准的地方、缺失的文件、歧义 |

**证据列必须填文件:行号**。只有"同上游写法"这类没有定位的说明，会被一致性分析判为无效。
